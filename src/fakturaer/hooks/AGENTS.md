- `linkSupplierItem` kaster `NothingSavedError` når et kall med `line_ids` endret 0 linjer (`assertScopedLinkSaved`); gjelder alle skjermer som kobler med fryst utvalg (leverandørvarens skjema, «Ikke vare», «Hopp over alltid», pakningsretting, Nye varer). Uten `line_ids` lagres kobling/vare også med 0 linjer. Why: serveren svarer ok uten å skrive når alle valgte linjer er låst, og det ble vist som lagret.

- `match-invoice-lines` er låst for internt godkjente fakturaer, med ett unntak: med eksplisitt `line_ids` og markøren `rm_cap_kobling_godkjent_v1` omregnes bare nettopp manuelt koblede linjer (`isFreshManualLink`), uten fakturastatus eller enhetsnormalisering (`approvedLinesOnlyAllowed` i `_shared/invoiceLifecycleGuard.ts`). Why: kobling på godkjent faktura skal gi prisobservasjon uten å endre godkjenningsgrunnlaget.
- EHF først (`supabase/pending/functions/_shared/ehfLines.ts` + `patches/20261119_ehf_forst.patch`): Tripletex-importen bruker EHF-linjer bare når hele dokumentet er komplett (linjesum på alle linjer, sum = dokument, eks. mva = Tripletex-hodet), ellers PDF-lesing for hele fakturaen; linjene går gjennom samme `toInvoiceLineRows`/ferdigstilling, og bryteren `invoice_reading_settings.ehf_first` er av som standard. XML tolkes alltid med `EHF_XML_OPTIONS` (alt som tekst), og trykt tillegg gir lesevarsel `tillegg`, aldri nettet inn i rabatten. Why: blandet kilde eller ufullstendig EHF ville gitt usporbare linjer, og tallkonvertering kuttet ledende nuller i varenummer.
- EHF-bryteren (`ehf_first`) lagres bare via `rm_save_ehf_first` fra kortet «EHF først»; `rm_save_reading_settings` rører den aldri, og manglende `ehf_first` i svaret er ukjent (bryter sperret), ikke AV. Why: lagring av de andre lesebryterne skal ikke kunne slå EHF av stille.
